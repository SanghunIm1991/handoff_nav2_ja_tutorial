環境構築：WSL2・ROS 2 Jazzy・Gazebo を入れる

Nav2 を試すには、その土台として Linux（Ubuntu）、ROS 2、シミュレーターの Gazebo が要る。Windows の PC なら、まず Windows の中で Linux を動かす仕組み（WSL2）を用意し、その上に順に積み上げていく。

この章の作業は、手を動かす時間よりも、ダウンロードと導入を待つ時間の方が長い。先にこの章を済ませておけば、次の Quickstart の章からは、Nav2 そのものに集中できる。後の章で使う開発の道具も、ここでまとめて入れておく。

このページについて

  • ROS 2・Gazebo・WSL の公式の文書の手順を基に、日本語でまとめ直したもの。逐語の翻訳ではない。出典とライセンスはページの末尾にある。
  • Windows 11 の WSL2 の上の Ubuntu 24.04 と、ROS 2 Jazzy を前提にする。Ubuntu 24.04 を直接入れた PC では、2 節を飛ばす。
  • 期待する結果の出どころ: 3 節の locale、5 節の Suites の行とパッケージの版、6 節の ROS_DISTRO、7 節の talker と listener、8 節の Gazebo の版と画面を出さない起動は、作成時の環境で、画面を出さずに確かめた。ただし作成時の環境は導入済みだったので、2 節〜5 節と 8 節の導入の手順そのものは頭から実行し直しておらず、導入のコマンドの表示（ダウンロードの進み方など）は載せていない。2 節の WSL の手順と、8 節の Gazebo の画面は、公式の文書から想定したもので、まだ確かめていない。
  • ログの角括弧の中の長い数字は時刻（UNIX 時刻）で、実行するたびに変わる。版の番号は、更新されると変わる。

0. 学習目標と完了条件

この章を終えると、次のことができる。

  1. Windows 11 の WSL2 に、Ubuntu 24.04 を入れられる。
  2. ROS 2 Jazzy と、後の章で使う開発の道具を、apt で入れられる。
  3. 2 つのターミナルでサンプルのプログラムを動かし、ROS 2 が動くことを確かめられる。
  4. Gazebo を入れて、起動できる。

完了条件は、7 節で listener が I heard と表示し、8 節で Gazebo が起動すること。

1. 全体像

この章で入れるものは、下から順に積み重なる。上のものは、すぐ下のものの上で動く。

  • WSL2（Windows Subsystem for Linux 2）: Windows の中で Linux を動かす、Microsoft の仕組み。Windows 11 では、Linux の画面のアプリも Windows のウィンドウとして開ける（この働きを WSLg と呼ぶ）。
  • Ubuntu 24.04: Linux の配布の 1 つ。ROS 2 Jazzy は、この版の Ubuntu の上で使うことを前提に作られ、試されている。
  • ROS 2 Jazzy: ロボットのプログラムを、役目ごとの node に分けて組み合わせるための仕組みと道具の集まり。Jazzy はその版の名前で、Nav2 もこの上で動く。
  • Gazebo Harmonic: ロボットと世界を計算で再現するシミュレーター。Harmonic は、ROS 2 Jazzy と組み合わせるよう勧められている版である。

2. WSL2 と Ubuntu 24.04 を入れる

Ubuntu 24.04 を直接入れた PC では、この節を飛ばして 3 節へ進む。

Windows のスタートメニューで PowerShell を右クリックし、「管理者として実行」で開く。まず、入れられる Linux の名前の一覧を確かめる。コマンドの箱の 1 行めの # PowerShell（管理者） は、「管理者の PowerShell で実行する」という印で、打たなくてよい。

# PowerShell（管理者）
wsl --list --online

期待する結果

入れられる Linux の名前（NAME の列）と説明が並ぶ。その中に Ubuntu-24.04 があることを確かめる（この表示は想定で、並び方や説明の文は時期によって変わる）。

# PowerShell（管理者）
wsl --install -d Ubuntu-24.04

-d の後には、一覧で確かめた名前をそのまま書く。WSL がまだ入っていない PC では、このコマンドが WSL2 そのものと Ubuntu 24.04 をまとめて入れる。途中で PC の再起動を求められたら、再起動する。

期待する結果

導入が終わると Ubuntu が起動し、Linux で使うユーザー名とパスワードを決めるよう求められる（想定）。ここで決めるのは Ubuntu の中だけのもので、Windows のユーザー名やパスワードとは別である。パスワードは、後の sudo（管理者の権限でコマンドを実行する）で使う。

以後、Ubuntu のターミナルは、スタートメニューの「Ubuntu 24.04」から開ける。3 節からのコマンドは、すべてこの Ubuntu のターミナルで実行する。

画面のアプリを使うための準備

8 節の Gazebo や、Quickstart の章の RViz は、画面を持つアプリである。Windows 11 の WSL2 では、これらがそのまま Windows のウィンドウとして開く。公式の文書は、そのために PC の GPU（Intel・AMD・NVIDIA）に合ったドライバを Windows に入れておくよう求めている。以前から WSL を入れていた PC では、管理者の PowerShell で wsl --update を実行して、WSL を新しくしておく。

3. Ubuntu を最新にし、locale を確かめる

ROS 2 のパッケージは、更新の進んだ Ubuntu の上で作られている。入れる前に、Ubuntu を最新の状態にしておく（ROS 2 の公式の手順も、こうするよう勧めている）。

# T1
sudo apt update

sudo apt upgrade

コマンドの箱の 1 行めの # T1 は、「1 つめの Ubuntu のターミナルで実行する」という印である（# から後はコメントなので、打たなくてよい）。7 節では、2 つめのターミナルを # T2 で表す。sudo apt update はパッケージの一覧を新しくし、sudo apt upgrade は入っているパッケージを新しい版にする。upgrade は、続けてよいかを [Y/n] で聞いてくるので、Y を押す。

次に、locale（言語や文字の符号化など、地域ごとの設定）が UTF-8 になっているかを確かめる。ROS 2 は UTF-8 を前提にしている。

# T1
locale

期待する結果

LANG=en_US.UTF-8
LANGUAGE=
LC_CTYPE="en_US.UTF-8"

実際にはこの後にも LC_ で始まる行が続く。LANG の値が .UTF-8 で終わっていればよい（ja_JP.UTF-8 など、ほかの言語でも UTF-8 ならかまわない）。

もし LANG=C や POSIX のように UTF-8 でなければ、ROS 2 の公式の手順どおり、次のように UTF-8 の locale を入れて設定する。最後の locale で、LANG=en_US.UTF-8 になったことを確かめる。

# T1
sudo apt install locales

sudo locale-gen en_US en_US.UTF-8

sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8

export LANG=en_US.UTF-8

locale

4. ROS 2 のリポジトリを足す

ROS 2 のパッケージは、Ubuntu が最初から見ている取り寄せ先（リポジトリ）には無い。ROS 2 のリポジトリを apt に教える。

まず、Ubuntu の universe というリポジトリ（コミュニティが保守するパッケージの置き場）を有効にする。ROS 2 は、そこにあるパッケージにも依存している。

# T1
sudo apt install software-properties-common

sudo add-apt-repository universe

次に、ROS 2 のリポジトリの設定と鍵をまとめたパッケージ ros2-apt-source を入れる。1 行めで GitHub の公開ページから最新の版の番号を調べ、2 行めでその版のパッケージを /tmp に取り寄せ、3 行めで入れる。2 行めの URL には、3 行めで使う Ubuntu の版の名前（24.04 なら noble）が、自動で埋め込まれる。

# T1
export ROS_APT_SOURCE_VERSION=$(curl -fsSL -o /dev/null -w '%{url_effective}' https://github.com/ros-infrastructure/ros-apt-source/releases/latest | awk -F/ '{print $NF}')

curl -L -o /tmp/ros2-apt-source.deb "https://github.com/ros-infrastructure/ros-apt-source/releases/download/${ROS_APT_SOURCE_VERSION}/ros2-apt-source_${ROS_APT_SOURCE_VERSION}.$(. /etc/os-release && echo ${UBUNTU_CODENAME:-${VERSION_CODENAME}})_all.deb"

sudo dpkg -i /tmp/ros2-apt-source.deb

curl が入っていないと言われたら、先に sudo apt install curl を実行する。入ったかどうかは、次のコマンドで確かめる。

# T1
dpkg-query -W ros2-apt-source

期待する結果

ros2-apt-source	1.3.0~noble

パッケージの名前と版が表示されれば、入っている。版の番号は、取り寄せた時期によって変わる。このパッケージは、以後の apt の更新で自動的に新しくなる。

5. ROS 2 Jazzy と開発の道具を入れる

ROS 2 の公式の手順は、Ubuntu 24.04 では apt の設定に基本の取り寄せ先（noble）しか入っていないことがあり、そのままでは開発の道具を入れるときに依存関係がぶつかりうる、と注意している。先に、設定を確かめる。

# T1
grep Suites /etc/apt/sources.list.d/ubuntu.sources

期待する結果

## Mirror your choices (except for URIs and Suites) in the security section below to
## Suites: The following additional suites can be configured
Suites: noble noble-updates noble-backports
## Ubuntu security updates. Aside from URIs and Suites,
Suites: noble-security

## で始まる行は説明のコメントで、見るのは Suites: で始まる行である。そこに noble-updates と noble-backports が入っていればよい。入っていなければ、そのファイルの Suites: noble の行を Suites: noble noble-updates noble-backports に書き換えてから、sudo apt update と sudo apt upgrade をやり直す（ファイルの書き換えには sudo が要る）。

ROS 2 Jazzy と、開発の道具を入れる。

# T1
sudo apt update

sudo apt upgrade

sudo apt install ros-jazzy-desktop

sudo apt install ros-dev-tools

ros-jazzy-desktop は、ROS 2 の本体に、RViz などの画面の道具とサンプルを加えたまとまりで、公式の手順が勧めているものである。量が多いので、この章でいちばん待ち時間が長い。

ros-dev-tools は、ROS 2 のプログラムをソースから組み立てるための道具のまとまりである。この章では使わないが、待ち時間を先に済ませるため、ここで入れておく。主な中身と、使う場面は次のとおり。

道具何をするか使う章
colcon複数の ROS 2 のパッケージを、依存の順にまとめてビルドするLocal Installation の章（Nav2 をソースからビルドする）。以後、自分のパッケージを作る章でも使う
rosdepソースのパッケージが必要とするほかのパッケージを調べ、apt でまとめて入れるLocal Installation の章
vcstool（コマンドは vcs）複数の Git のリポジトリを、一覧のファイルからまとめて取得するLocal Installation の章

入ったかどうかは、次のコマンドで確かめる。

# T1
dpkg-query -W ros-jazzy-desktop ros-dev-tools

期待する結果

ros-dev-tools	1.0.3
ros-jazzy-desktop	0.11.0-1noble.20261105.164848

2 つのパッケージの名前と版が表示されれば、入っている。版の番号は、入れた時期によって変わる。

6. 環境を読み込む

ROS 2 のコマンド（ros2 など）は、入れただけではターミナルから見つからない。ROS 2 の場所を、今のターミナルに教える必要がある。

# T1
source /opt/ros/jazzy/setup.bash

echo $ROS_DISTRO

期待する結果

jazzy

source は、ファイルに書かれた設定（コマンドやパッケージの場所を表す環境変数など）を、今のターミナルに読み込む。その設定の 1 つ ROS_DISTRO が jazzy と表示されれば、読み込めている。この設定はそのターミナルの中だけで有効なので、ターミナルを新しく開くたびに source が要る。この教材のコマンドの箱でも、新しいターミナルでは毎回 source から書いている。

毎回の source を省く方法と、この教材で使わない理由

ターミナルを開くたびに自動で読み込まれる設定のファイル ~/.bashrc に、source の行を 1 回だけ書き足しておく方法がある。

echo "source /opt/ros/jazzy/setup.bash" >> ~/.bashrc

こうすると、以後に開くターミナルでは最初から ROS 2 が使え、source を打ち忘れて「コマンドが見つからない」と困ることもなくなる。ROS 2 だけを使う PC なら、手間が大きく減る。

一方で、この設定は、その PC で開くすべてのターミナルに効く。同じ PC で、ROS 2 を使わないほかのプロジェクトや、別の版の ROS 2 を扱うと、意図しない環境が読み込まれて、原因の分かりにくい食い違いが起きうる。後の Local Installation の章で、ソースからビルドした Nav2 を読み込むときにも、どの環境を読み込んでいるかが見えにくくなる。そのため、この教材では書き足さず、ターミナルごとに source する形にしている。書き足した後で外したいときは、~/.bashrc の最後の行を消す。

7. 動作を確かめる

ROS 2 のサンプルの node を 2 つ動かし、やり取りできるかを確かめる。talker は「Hello World」という文を 1 秒ごとに topic へ送り、listener はそれを受け取って表示する。T1 で talker を動かしたまま、新しい Ubuntu のターミナル（T2）を開いて listener を動かす。

# T1
source /opt/ros/jazzy/setup.bash

ros2 run demo_nodes_cpp talker
# T2
source /opt/ros/jazzy/setup.bash

ros2 run demo_nodes_py listener

ros2 run は、パッケージ（ここでは demo_nodes_cpp と demo_nodes_py）の中の node を 1 つ起動するコマンドである。talker は C++、listener は Python で書かれているので、両方の言語で ROS 2 が動くことを一度に確かめられる。

期待する結果

T1（talker）:

[INFO] [1795261361.550521195] [talker]: Publishing: 'Hello World: 1'
[INFO] [1795261362.550394776] [talker]: Publishing: 'Hello World: 2'
[INFO] [1795261363.550229313] [talker]: Publishing: 'Hello World: 3'
[INFO] [1795261364.550583601] [talker]: Publishing: 'Hello World: 4'

T2（listener）:

[INFO] [1795261364.568141991] [listener]: I heard: [Hello World: 4]
[INFO] [1795261365.552197188] [listener]: I heard: [Hello World: 5]
[INFO] [1795261366.552076670] [listener]: I heard: [Hello World: 6]
[INFO] [1795261367.551799647] [listener]: I heard: [Hello World: 7]

talker の Publishing の番号と、listener の I heard の番号が対応していれば、やり取りできている。listener は、起動した時点より後に送られたものから受け取るので、最初の番号は 1 とは限らない（作成時は 4 から）。ros2 run は起動に数秒かかることがあり、表示が出るまで少し待つ。確かめたら、T1 と T2 の両方で Ctrl+C を押して止める。

8. Gazebo を入れて確かめる

ROS 2 Jazzy からは、Gazebo も ROS 2 のリポジトリから入れられる。次のコマンドは、ROS 2 と Gazebo をつなぐパッケージ群 ros_gz と、それに合った版の Gazebo（Jazzy では Harmonic）をまとめて入れる。Gazebo の公式の文書も、特に理由が無ければこの方法を勧めている。

# T1
sudo apt install ros-jazzy-ros-gz

Gazebo の gz コマンドも、ROS 2 の環境を読み込んだターミナルで使えるようになる。版を確かめる。

# T1
source /opt/ros/jazzy/setup.bash

gz sim --version

期待する結果

Gazebo Sim, version 8.15.0
Copyright (C) 2018 Open Source Robotics Foundation.

実際にはこの後にもライセンスの文が続く。version 8 で始まる版が、Gazebo Harmonic である。細かい番号は、更新されると変わる。

最後に、何も無い世界を Gazebo で開く。

# T1
gz sim empty.sdf

期待する結果

Gazebo のウィンドウが開き、地面だけの世界が表示される（想定）。画面のアプリを初めて開くときは、ウィンドウが出るまで時間がかかることがある。確かめたら、T1 で Ctrl+C を押すか、ウィンドウを閉じる。

画面を出さずに、Gazebo の計算の部分（サーバー）だけが動くかを確かめることもできる。-s はサーバーだけを動かす指定、-r は読み込んだらすぐに時間を進める指定である。

# T1
gz sim -s -r -v 3 empty.sdf

期待する結果

[Msg] Gazebo Sim Server v8.15.0
[Msg] Loading SDF world file[/opt/ros/jazzy/opt/gz_sim_vendor/share/gz/gz-sim8/worlds/empty.sdf].
[Msg] Serving entity system service on [/entity/system/add]

実際には、この後にも [Msg] で始まる行が続く（作成時の表示は色つきで、その色の制御文字は除いた）。2 行めで、Gazebo が ROS 2 の場所（/opt/ros/jazzy）の中に入った世界のファイルを読み込んでいることが分かる。止めるときは Ctrl+C を押す。

9. 製品に組み込むなら

この章で作ったのは、開発と学習のための環境である。製品のロボットに載せるコンピューターでは、考えることが変わる。

この章で用意したもの製品では
Windows 11 の WSL2 の上の Ubuntu 24.04ロボットに載せるコンピューターには、Ubuntu 24.04 を直接入れるのが基本になる。WSL2 は、開発用の PC で使う。ROS 2 Jazzy の公式の deb パッケージは、amd64（一般の PC）と arm64（多くの小型のボードのコンピューター）の両方に用意されている。
ros-jazzy-desktop（RViz などの画面の道具を含む）画面を持たないロボットには、公式の手順にある画面の道具を含まないまとまり ros-jazzy-ros-base を入れ、必要なパッケージだけを足す。
sudo apt upgrade で、いつでも最新の版にする更新でパッケージの版が変わると、動きが変わりうる。製品では、使う版を決めて試験してから更新する。ROS 2 の公式の文書は、古い版の状態を入れ直すためのリポジトリ（snapshot repository）も案内している。
ROS 2 JazzyROS 2 の版には、サポートの期限がある。Jazzy の期限は 2029 年 5 月（ROS の版の計画を定めた文書 REP 2000 による）。製品を出す時期と保守する期間を考え、どの版の上に作るかを決める。
