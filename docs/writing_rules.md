# 書き方の決まり

教材のページ（HTML・Markdown）を書く・直すときの決まり。`CLAUDE.md` の「進め方」の 2（書く）から指される。サイトには載せない（`_config.yml` の `exclude`）。2026-11-21 に `CLAUDE.md` から移した（常に読み込まれる文書を軽くするため）。


学習用のテキストの書き方の全般は `learning-text-authoring` スキル。それに加えて、このリポジトリでは次の決まりを守る。

- **Nav2 と ROS 2 の専門用語は英語のまま書く**（costmap・planner・controller・behavior tree、node・topic・launch file・odometry など）。カタカナにすると覚える言葉が増えるため。一般の言葉のカタカナ（ロボットなど）は避けなくてよい。初出で意味を 1 文で書く。英語の用語と日本語の間には半角の空白を入れる（句読点・括弧の隣には入れない）。
- **AI が作成した旨**: 各ページの末尾の注記と用語集に、「作成者の指示のもとで、Anthropic の AI である Claude（Claude Code）が作成した」旨を書く。
- **用語集**: 英語の用語と日本語での 1 文の意味を並べたページ。読者向けであると同時に、ユーザーと Claude の開発の共通言語でもある。本文に出てきた用語だけを載せ、網羅を目指さない。用語の意味が決まったり、会話と用語集が食い違ったりしたら `domain-modeling` スキルに従って用語集を更新し、会話と本文でも用語集の語を使う。
- **製品に組み込むなら**: 各ページの末尾に、この見出しの短い節を置く。そのページでシミュレーションや手の操作が代わりに担っていたことを、製品ではどう置き換えるか（何を考える必要があるか）を書く。毎ページ同じ見出しにして、拾い読みできるようにする。
- **期待する結果**: コマンドや node を実行する手順の直後に、「期待する結果」の見出しと、表示の例と読み方を置く。HTML のページでは、Quickstart の形にそろえる: `<div class="expect">` の中に `<h4>期待する結果</h4>`、表示の例は `<pre class="out">`、読み方は `<div class="prose">`。実行するコマンドは `<pre class="cmd">`。この方針の説明はサイトのトップに 1 か所だけ書き、各ページでは繰り返さない（Quickstart の見た目にユーザーの不満が出たら、この形ごと見直す）。
- **期待する結果の出どころ**: 各ページの冒頭の注記にまとめる。表示ごとに、ユーザーが画面で確かめたもの・Claude が画面なしで確かめたもの・想定（コードと仕様から）を区別する。ページの文では役割を書かず（「教科書の口調」）、「作成時の環境で画面で確かめた」「作成時の環境で、画面を出さずに確かめた」「想定（ソースと公式の説明から）」のように書く。実行ごとに変わる部分（時刻・pid・パス）は、その旨を書く。
- **コマンドのブロック**: 実行するコマンドだけを書く。別のターミナルは `# T1`・`# T2` で区切り、コマンドとコマンドの間に空行を 1 行入れる。`# T1` の意味（「1 つめのターミナルで実行する印。`#` から後はコメントなので打たなくてよい」）は、サイトのトップに書き、各ページでも最初の `# T1` の場面に一言添える（どのページから読み始めても分かるように）。出力は `text`、ファイルに書く内容はその言語のブロックにする。
- **サンプルのファイルのパス**: サンプルのコードの前に「ファイル: `ros2_ws/src/...`」の行を置き、置き場所を具体的に示す。
- **概要のコメント**: サンプルには、クラス・関数ごとに 1〜2 行の概要コメントを書く。
- **参照の書き方**: ほかのページは「〇〇の章」のように名前で、同じページの節は「4-2 節」と書く（数字だけでは、ページか節かが分からないため）。前方参照は、どの節の何か（中身の要約）まで書く。
- **標準の型へのリンク**: ROS 2 の標準のメッセージ型は、各ページの初出で、`ros2` の公式リポジトリの `jazzy` ブランチにある定義ファイルへリンクする（`raw.githubusercontent.com` の同じパスが 200 を返すことを確かめる）。
- **教科書の口調**: 「ユーザーが行う」「差分を貼ってほしい」など、役割分担を前提にした言い回しを本文に書かない。特定の練習環境で気づいたことは、教材ではなく `notes/`（Git 管理外）に書く。
- **情報はその場で**: 理解に要る情報を後の節に送らない。詳細は Tips のページへ移す。
- **作成環境に由来する値**: ログの UNIX 時刻・ビルドの秒数・RTF などは、学習者が見比べる材料になるので残してよい。メモリやディスクの量など PC の具体的な値と、PC の用途の例は書かない。
